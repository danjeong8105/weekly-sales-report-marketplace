# 주간 매출 리포트 → 슬랙

구글 시트의 판매내역을 집계해 지난주 리포트를 슬랙 채널에 올린다.
채널에는 제목 한 줄만 보내고, 리포트 본문은 그 메시지의 스레드에 단다.

## 입력 확인

사용자가 말하지 않은 값만 묻는다. 이미 말한 값은 다시 묻지 않는다.

- 시트 이름 (예: `판매관리10.29`). `판매내역` 시트에 열이 있어야 한다: 주문일, 주문번호, 판매채널, 카테고리, 상품명, 옵션, 수량, 판매단가, 결제금액, 배송비
- 슬랙 채널 (없으면 만들지 말고 먼저 물어본다)
- 지난주 기간: 별도 지정이 없으면 오늘 기준 직전 월~일

리포트를 만들기 전에 아래 기준을 사용자에게 물어본다 (AskUserQuestion). 이전 실행에서 쓴 기본값을 권장 옵션으로 둔다.

1. 매출 기준: 결제금액 합계(권장, 배송비 별도) / 결제금액 + 배송비
2. 비교 기준: 전주 대비(권장) / 전주 + 전월 동기 / 비교 없음
3. 포함 항목: 핵심 지표, 판매채널별, 카테고리별, 매출 TOP 5 상품 + 일별 추이
4. 형식: 스레드 댓글 1개(권장) / 여러 개

## 절차

1. 드라이브에서 시트를 찾는다 (`search_files`, mimeType 스프레드시트).
2. `download_file_content`로 `text/csv`를 받는다. 결과가 커서 파일로 저장되고, JSON의 `content`는 base64다. 컨텍스트에 직접 읽지 않는다. `read_file_content`는 샘플 일부만 주므로 집계에 쓰지 않는다.
3. 집계 스크립트를 실행하고 결과를 파일로 받아 Read로 읽는다. Bash 콘솔은 한글이 깨질 수 있어 `-X utf8`과 파일 리다이렉트를 쓴다.
   ```bash
   python -I -X utf8 <이 스킬 폴더>/scripts/aggregate.py <저장된 JSON 경로> > <스크래치패드>/out.txt
   ```
   `--today YYYY-MM-DD`로 기준일을 바꿀 수 있다. 출력의 `title`이 채널 첫 줄이다.
4. 검증: 출력의 `total_revenue_all_rows`가 시트 `대시보드`의 총 매출과 같은지 확인한다. 다르면 보내지 말고 원인을 먼저 찾는다. 지난주 데이터가 0건이면 보내지 않고 알린다.
5. 슬랙 `slack_read_channel`로 채널을 읽어 `title`과 같은 첫 줄의 메시지가 있는지 확인한다. 있으면 보내지 않고 해당 메시지 링크를 알린다.
6. 없으면 `slack_send_message`로 `title` 한 줄만 보낸다. 반환된 `message_ts`를 저장한다.
7. 같은 채널에 `thread_ts`=위 `message_ts`로 리포트를 스레드 댓글로 단다 (`reply_broadcast` 사용 안 함).
8. 사용자에게 전송한 메시지와 스레드 링크, 핵심 수치 2~3줄을 알린다.

## 리포트 형식

마크다운 표를 쓴다. 항목 순서: 핵심 지표 → 판매채널별 → (카테고리별) → 매출 TOP 5 상품 → 일별 매출 추이.

- 핵심 지표: 총 매출, 주문 건수, 판매 수량, 객단가, 배송비 합계. 열은 지난주 / 전주 / 증감
- 판매채널별: 매출, 비중, 주문 건수, 전주 대비 증감률
- 증감률은 소수 첫째 자리까지, 금액은 천 단위 쉼표와 `원`
- 전주 TOP 5에 없던 상품은 증감률을 계산할 수 없으므로 비교를 생략한다
- 마지막 줄에 기준을 이탤릭으로 적는다: 매출 정의, 주문 건수는 주문번호 중복 제외, 출처 시트 이름

## 주의

- 같은 주문번호가 여러 줄에 걸쳐 있으므로 주문 건수는 줄 수가 아니라 고유 주문번호 수다.
- 슬랙 전송은 사용자가 요청한 채널에만 한다. 중복 확인에서 걸리면 재전송하지 않는다.
- 이 스킬은 시트나 슬랙 설정을 바꾸지 않고, 파일은 스크래치패드에만 만든다.
